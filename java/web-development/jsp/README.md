## JSP (Java Server Pages)
>JavaServer Pages (JSP) allows dynamic content injection into static contents using Java and Java Servlets. 

**JSP files are essentially .html files** with some extra syntax, and a couple of minor initial differences:
1. the .html suffix is replaced with .jsp (it’s considered a .jsp filetype) and
2. the following tag is added to the top of the .html markup elements:
```jsp
<%@ page contentType="text/html;charset=UTF-8" language="java" %>
```

## JSP Syntax
Java code can be injected in two ways
### 1. Scriptlet Tags
```jsp
<% Java code here %>
```
### 2. XML Tag
```jsp
<jsp:scriptlet>
    Java code here
</jsp:scriptlet>
```

## JSP Tags
There are four more tags which has specific responsibilities

### 1. Regular Scriptlet Tag
```jsp
<% Java code here %>
```
Code inside Regular Scriptlet Tag is executed for every request.

### 2. Declaration Tag
```jsp
<%! Declaration Here %>
```
- Code inside declaration tags is evaluated only once when the JSP is compiled.

- So, we can declare methods or variables which doesn't change on any request.

- JSP declarations may also be used to define class-level fields:

    ```jsp
    <%! private int visitCount = 0; %>
    
    <% visitCount++; %>
    <p>Page visits: <%= visitCount %></p>
    ```
    - This approach is not thread-safe and can lead to unexpected behavior in a multi-user environment.
    - Because declared fields are shared across all requests handled by the same servlet instance.

### 3. Expression Tag
```jsp
<%= Expression Here %>
```
- The expression tag `(<%= … %>)` is used to render the returned value directly into the HTML output.
- Expression Tag supports **conditional operator**.

### 4. Directive Tag
```jsp
<%@ Directive directive-attributes %>
```
- JSP supplies out of the box directives that can be used to specify core functionalities for our JSP files.

## Implicit Objects
Implicit objects are generated by the JSP engine automatically during compilation.
### List of implicit objects
#### 1. request
`request` belongs to the class `jakarta.servlet.http.HttpServletRequest`. The request object exposes all user input data and makes it available serverside.
#### 2. response
`response` belongs to the class `jakarta.servlet.http.HttpServletResponse` and determines what is passed back clientside after a request is made.
#### 3. out
`out` belongs to the class `jakarta.servlet.jsp.JspWriter` and is used to write content to the client.
- Anything that is written into out is written to response in two steps:
  - Writes the content to memory
  - Writes content to response object from memory
- **To be more performant** we use `PrintWriter` since it allows to write directly to the response object!

#### 4. session
`session` belongs to the class `jakarta.servlet.http.HttpSession` maintains user data for the duration of the session.

#### 5. application
`application` belongs to the class `jakarta.servlet.ServletContext` stores application-wide parameters set at initialization or that need to be accessed application-wide.

#### 6. exception
`exception` belongs to the class `jakarta.servlet.jsp.JspException` is used to display error messages on JSP pages which have the tag `<%@ page isErrorPage=”true” %>`.

#### 7. page
`page` belongs to the class `java.lang.Object` allows one to access or reference current servlet information.

#### 8. pageContext
`pageContext` belongs to the class `jakarta.servlet.jsp.PageContext` defaults to page scope but can be used for accessing request, application, and session attributes.

#### 9. config
`config` belongs to the class `jakarta.servlet.ServletConfig` is the servlet configuration object allowing one to get the servlet context, name, and configuration parameters.

## Directives
There are two parts to JSP directives: 
1. The directive itself 
2. The attribute of that directive which is assigned a value.

The three kinds of directives that can be referenced using directive tags
1. `<%@ page … %>` which defines dependencies and attributes of the JSP including content type and language.
2. `<%@ include … %>` which specifies an import or file to be used.
3. `<%@ taglib …%>` which specifies a tag library defining custom actions to be used by a page.
