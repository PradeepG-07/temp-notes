## Runners
Runners are executed by spring boot when the application starts.

### Use Cases
1. Seed initial data
2. Perform startup validations like all environment variables are injected etc.
3. Initialize/Pre load caches
4. Schedule/Start Background workers
5. Run CLI Style applications

<hr />

In Spring Boot, there are **two built-in runner interfaces** intended for startup execution:
### 1. ApplicationRunner
Receives an `ApplicationArguments` object, which provides convenient access to option and non-option arguments:
Options look like `--optionName=optionValue`

Some of the methods of `ApplicationArguments` class are as follows:  
1. **`getOptionNames`**: Return a `List<String>` of option names
2. **`containsOption`**: Return a `boolean` if option name is provided.
3. **`getOptionValues`**: Return a `List<String>` of option values provided
4. **`getNonOptionArgs`**: Return a `List<String>` of non option arguments

This runner can be used when we need to parse the command line options provided.

```java
@Component
class MyRunner implements ApplicationRunner {
    @Override
    public void run(ApplicationArguments args) {
        if (args.containsOption("env")) { 
            String env = args.getOptionValues("env").get(0);
            System.out.println("Environment: " + env); 
        } 
        if(args.containsOption("role")){
            List<String> roles = args.getOptionValues("role");
            System.out.println(roles);
        }
        System.out.println("Files: " + args.getNonOptionArgs());
    }
}
```

```bash
java -jar app.jar --env=prod --role=py-admin --role=cp-admin users.csv orders.csv
```

**Output**
```txt
Environment: prod
[py-admin, cp-admin]
Files: [users.csv, orders.csv]
```

### 2. CommandLineRunner
Receives startup arguments as a raw `String[]`:
```java
@Component
class MyRunner implements CommandLineRunner {
    @Override
    public void run(String... args){
        for(String arg: args)
            System.out.println(args);
    }
}
```
